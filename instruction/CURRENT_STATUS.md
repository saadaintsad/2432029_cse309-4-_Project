  Bug fix — /admin/documents PDF crash: root cause was an architectural mistake in how @react-pdf/renderer was being loaded. CashMemoForm.tsx and ColorSlipForm.tsx were separately wrapping `PDFDownloadLink` and the PDF `<Document>` component (CashMemoPDF/ColorSlipPDF) in two different `next/dynamic()` calls, then combining them at render time. @react-pdf/renderer's `<Document>`/`<Page>` tree isn't processed by ReactDOM — it's handed to react-pdf's own internal layout/PDF renderer, which needs a fully-resolved element tree built by a component that imports react-pdf directly. Passing it through an intermediate next/dynamic() loading-proxy meant react-pdf's internals sometimes received the wrong kind of node and crashed trying to read something off it — hence "reading 'stack'" on undefined.
  Fixed exactly per your four points:
  1. Added 'use client' to every module that imports from @react-pdf/renderer that didn't already have it: components/pdf/font.ts, styles.ts, CashMemoPDF.tsx, ColorSlipPDF.tsx (the PDF components themselves were client components before, but the leaf modules they imported weren't explicitly marked, which is the belt-and-suspenders fix you asked for).
  2. Moved PDF generation into two new dedicated client-only files — components/admin/documents/CashMemoDownload.tsx and ColorSlipDownload.tsx — each of which statically imports PDFDownloadLink and its matching PDF document component directly (no nested dynamic() inside them) and exports one component that renders the complete `<PDFDownloadLink document={<CashMemoPDF .../>}>...</PDFDownloadLink>` tree as a single unit.
  3. CashMemoForm.tsx and ColorSlipForm.tsx now each do exactly ONE `dynamic(() => import('./CashMemoDownload'), { ssr: false })` (same for ColorSlipDownload) instead of two separate dynamic wrappers for the link and the document — this was the actual fix; everything else was reinforcing it.
  4. The PDF viewer/download button is now guaranteed never rendered server-side: the whole `CashMemoDownload`/`ColorSlipDownload` component is the ssr:false dynamic import, and it's the only thing that touches react-pdf's actual rendering primitives beyond the pure-data PDF document components.
