Not a concern for this app's actual deployment (Vercel + real browsers), just worth knowing if it's ever tested in a fully air-gapped environment.
  - Any change to next.config.mjs requires a dev server restart to take effect — Next.js does not hot-reload it.
  - Next.js's fetch Data Cache can silently serve stale results for direct Supabase reads in Server Components that don't otherwise trigger dynamic rendering (no cookies/headers/searchParams) — this was a real bug (see above), now fixed at the source in `createServiceRoleClient()` (always `cache: "no-store"`). Any brand-new Server Component added later that reads live data should still also get `export const dynamic = "force-dynamic"` on principle, but the actual protection comes from the shared client, not that export alone.
